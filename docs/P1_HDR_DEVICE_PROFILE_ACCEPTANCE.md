# P1 HDR / 10-bit 设备档案与真机验收

本文用于验收 Localis P1 的高画质双路径：在证据充分时尝试原片，在证据不足或运行失败时使用兼容流。它不是设备兼容性宣传材料；未完成对应真机检查的组合不得标记为“已支持 HDR”。

## 可信边界

- `MediaCapabilities`、`canPlayType` 或浏览器成功解码，只能说明解码路径可能可用，不代表视频最终以 HDR、正确 EOTF、正确色域或正确峰值亮度呈现。
- WebXR 会话成功、视频纹理持续更新，也不等于合成器和头显面板保留了 HDR。当前浏览器接口不能单独证明端到端 HDR 呈现。
- Localis 本地引导产生的 `guided-user` 证据只表示“用户在这台设备上目视确认过这一部精确片源的原片效果可接受”，不能显示为“已验证 HDR”。当前本地档案只接受 `guided-user`；可编辑的 localStorage JSON 即使写成 `instrumented` 或 `vendor-attested` 也必须拒绝。未来只有经过签名验证的仪器或厂商证明才可标为已验证呈现。
- HDR10、HLG 和显式 SDR 传递特性的 10/12-bit 内容（下文称 `sdr10`）可以建立人工设备档案。Dolby Vision（`dolby-vision`）和色彩元数据缺失或冲突（`unknown`）不得建立或复用本地持久确认。
- 原片尝试绝不修改源文件。HDR10/HLG 兼容流会在电脑端映射为 SDR BT.709；10/12-bit 会抖动量化为 8-bit。抖动用于减轻色带，但转换仍然有损。Dolby Vision 不执行动态元数据重建；基底传递函数不明确的 Dolby Vision 与 `unknown` 只输出色彩未知的 8-bit 兼容画面，不得称为 SDR 色彩正确。

## 人工真机确认流程

适用范围仅为元数据完整的 `hdr10`、`hlg` 或 `sdr10` 片源。

1. 在要验收的头显及系统浏览器中，通过可信 HTTPS 地址打开 Localis，记录设备型号、系统版本、浏览器引擎及主版本、访问 `origin` 和 Localis 版本。
2. 选中目标片源，保存该片源的诊断 JSON。确认诊断包含精确媒体元数据，且动态范围不是 Dolby Vision 或 `unknown`。
3. 手动选择“原始 HDR/10-bit 实验尝试”，进入 WebXR 沉浸会话。
4. 在同一次会话中连续观看至少 10 秒。观察高光是否剪切、暗部是否压黑、肤色/色相是否异常、渐变是否出现明显色带，以及双眼布局、帧推进和音画同步是否正常。
5. 退出 WebXR。只有实际完成上述观察并认为画面可接受，才点击保存本片的人工确认；不得仅因视频能够开始播放就确认。
6. 刷新页面并再次打开同一片源。诊断应显示 `guided-user`、仍未仪器验证，并允许原片路径。再次进入 WebXR，确认播放正常。
7. 保存诊断 JSON、截图或录屏和人工观察结论。记录文字应为“本设备人工确认本片原片效果可接受”，不得写成“设备已验证支持 HDR”。

如果未进入 WebXR、沉浸观看不足 10 秒、播放中断，或在退出会话前没有完成观察，界面不得开放保存确认。

## 档案作用域与失效

人工确认最多有效 90 日，并且只对完整匹配的组合生效：

- 当前 Localis 安装生成的 installation UUID；
- HTTPS `origin`；
- 浏览器产品（含 Meta Quest / PICO Browser）、引擎及主版本；
- 操作平台、`webxr` 呈现方式和播放器管线版本；
- 完整媒体元数据指纹：媒体 ID、文件大小、修改时间、封装、编码、profile、level、像素格式、位深、动态范围、原色、传递函数、色彩矩阵、色彩范围、宽高、帧率、投影方式和立体布局。

任一绑定项变化都必须失效并重新确认。该指纹不是整文件密码学哈希；如果以相同大小、修改时间和全部探测元数据替换文件，必须主动撤销档案并重新扫描。档案保存在当前浏览器的本地存储中，不得当作可跨域、跨浏览器、跨设备、跨片源或跨 Localis 安装迁移的能力声明。存储损坏、未知 schema 或字段不完整时必须关闭授权，不能静默重建并继续信任。

## 兼容流应显示的信息

| 输入分类 | 兼容流标签必须表达 | 不得声称 |
| --- | --- | --- |
| HDR10 / HLG | `HDR → SDR BT.709`，电脑端色调映射 | HDR 直出、保留原始 EOTF |
| `sdr10` | `10/12-bit → 8-bit`，带抖动的有损量化 | 保留 10/12-bit 精度 |
| Dolby Vision | 不受本地档案授权；明确基底仅作未认证映射，否则输出 8-bit 色彩未知兼容流 | Dolby Vision 重建、认证 SDR 或浏览器已保留 Dolby Vision |
| `unknown` | 元数据不足，只输出 8-bit H.264 色彩未知兼容流 | 根据“能播放”推断 HDR/SDR、亮度或色彩正确 |

原片路径对 HDR 或高位深内容必须显示“实验尝试”或等价的不确定性提示。`guided-user` 可以显示“本设备人工确认”，但 `presentationVerified` 必须仍为 false；只有 `instrumented` 或 `vendor-attested` 证据可以显示已验证呈现。

## 必测验收矩阵

每一项都应在真实头显上保存切换前后的诊断 JSON，并确认页面标签与实际网络路径一致。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 无档案 | 首次打开 HDR10、HLG 或 `sdr10` 片源 | 默认使用安全兼容流；可以手动进入原片实验尝试，但不能显示已验证呈现 |
| 有效精确档案 | 按流程观看至少 10 秒、退出 WebXR、确认并刷新 | 仅同一环境和同一精确媒体获得 `guided-user` 授权；可选原片，仍明确“人工确认、非仪器验证” |
| 档案过期 | 将验收时间推进到 `expiresAt` 或之后 | 档案不再授权，原因显示为过期，默认回到兼容流并要求重新确认 |
| 浏览器主版本升级 | 在其他绑定均不变时改变浏览器主版本 | 原档案不复用，原因显示为浏览器主版本变化；重新执行 10 秒确认流程 |
| 浏览器小版本变化 | 主版本不变，仅升级小版本 | 不因小版本本身失效；仍须进行一次运行播放检查，失败时立即回退 |
| `origin` 变化 | 用不同域名、端口或协议访问 | 原档案不复用，原因显示为 origin 不匹配；不得跨 origin 复制授权 |
| 源文件变化 | 替换文件、改变大小或修改时间，或改变任一编码/画面/投影字段 | 精确媒体指纹不匹配，默认回到兼容流；相同媒体 ID 也不得绕过 |
| 其他片源 | 打开动态范围相同但媒体指纹不同的影片 | 不复用确认，必须为新片源单独观察并确认 |
| Dolby Vision | 播放可被解码的 Dolby Vision 文件并尝试保存 | 不提供持久确认；解码成功也不能授权 Dolby Vision 呈现 |
| `unknown` | 播放元数据缺失或冲突的高位深文件并尝试保存 | 不提供持久确认；使用保守兼容流并提示色彩准确性未验证 |
| 原片运行失败 | 有效档案下模拟解码错误、停帧或原片媒体错误 | 当前播放自动切到兼容流，播放位置尽量保持；不得循环重试原片或把失败隐藏为 HDR 成功 |
| 撤销单片确认 | 对当前档案执行撤销后重新加载 | 已撤销档案不再授权；同一片源恢复默认兼容流，其他片源档案不受影响 |
| 重置全部档案 | 执行设备档案重置并重新加载 | 本地档案存储被移除，所有片源恢复无档案状态；新建档案需生成新的安装身份并重新走完整流程 |
| 存储损坏/未知版本 | 注入非法 JSON 或未知 schema | 安全失败，不自动授权；界面解释原因并只允许显式重置 |
| 管线或平台变化 | 改变播放器管线版本、平台或呈现方式 | 原档案不复用，回到兼容流并要求重新验证 |

## 发布门槛

- 自动化测试通过不替代 Vision Pro、Quest、PICO 真机验收。
- 每一条对外兼容声明必须对应“设备型号 + OS + 浏览器主版本 + 精确样片 + Localis 管线版本”的证据记录。
- 只有人工确认时，发布说明应使用“已在该组合目视确认原片效果可接受”；没有仪器或厂商证据时，不得使用“端到端 HDR 已验证”“杜比视界已认证”等表述。
- 任一回退、撤销、失效或存储损坏场景未通过，P1 设备档案功能不得标记为完成。
