# Localis 后续开发路线图

更新时间：2026-08-25

Localis 的产品定位保持不变：**零安装、私有化、带 AI 增强和网盘接入的 XR 媒体网关**。头显只使用系统浏览器；媒体、凭据、证书私钥、转码缓存和 AI 计算留在用户电脑。

本文记录 P1 之后尚未完成的工作。路线图中的“完成”必须同时满足实现、自动化验证和对应真实环境验收，不能用浏览器可解码或 WebXR 会话成功替代端到端画质证明。

## 当前基线

- [x] P0：建立原片直连、兼容 HLS、电脑端超分和明确的实际播放路径标签。
- [x] P1 代码：完成 HDR10、HLG、高位深 SDR、杜比视界与未知色彩信号的保守分类；兼容流支持色调映射与抖动降位深。
- [x] P1 代码：完成按安装、来源、设备、浏览器主版本和精确媒体元数据绑定的人工显示确认，并提供失效、撤销和安全回退。
- [x] P1 自动化：类型检查、Lint、生产构建和 263 项测试通过。
- [ ] P1 真机：Vision Pro、Quest、PICO 的 HTTPS、WebXR、HDR/高位深观感和长时间稳定性仍需按验收清单逐项执行。

## 优先级原则

1. 安全兼容路径必须始终可用，实验原片路径不能破坏默认播放。
2. 先解决播放失败、卡顿、音画不同步和错误恢复，再增加画质选项。
3. 不要求头显安装 App、证书、扩展或 AI 运行时。
4. 不把私人媒体、网盘凭据或 AI 任务迁移到第三方云端。
5. 所有 HDR、杜比视界、空间音频和设备兼容声明都必须绑定可复查的真机证据。

## P2：真机闭环与播放可靠性（下一优先级）

P2 是下一次对外发布前的阻断项，目标是把已经通过自动化的播放管线变成可重复验证的真实头显体验。

### P2.1 可信 HTTPS 与设备矩阵

- [ ] 使用真实域名完成一次公共可信 DNS-01 证书签发，媒体流只在局域网传输。
- [ ] 提供 Cloudflare DNS 的可重复配置流程，并为阿里云域名保留迁移 DNS 或新增 AliDNS ACME 适配的说明。
- [ ] 建立 `设备型号 + OS + 浏览器主版本 + Localis 管线版本` 兼容矩阵。
- [ ] 在 Vision Pro、Quest、PICO 上分别完成首次配对、普通播放、VR180、VR360、字幕、退出/重进 WebXR 和待机恢复。
- [ ] 明确区分“网页视频可播放”“WebXR 可进入”“人工观感可接受”和“仪器/厂商验证 HDR”。

验收标准：三类目标头显打开 HTTPS 无证书警告；必测项全部记录诊断 JSON；未经验证的组合不进入 README 兼容声明。

### P2.2 构建、启动与错误恢复

- [ ] 生产构建采用版本化目录和原子切换，至少保留 N-1 版本静态资源，禁止运行中的旧前端引用已删除的哈希资源。
- [ ] 构建完成后由统一启动器有序重启前端，并在 8080/8081 网关层保留可读的启动状态页。
- [ ] 客户端检测资源版本不匹配后只自动刷新一次，失败时显示可操作的恢复提示，避免无限骨架屏。
- [ ] 前端与 API 进行 build ID 握手；Three.js、hls.js 等大依赖按播放路径延迟加载，并设置首屏资源预算。
- [ ] 桌面壳监督前端与 API 子进程，加入健康检查、退避重启、启动超时诊断和用户可见的故障状态。
- [ ] 为禁用本地存储、WebGL 上下文创建失败、媒体源异常和 HLS 任务失败增加错误边界与兼容回退。

验收标准：连续执行 20 次“构建—重启—打开媒体—进入播放页”，不再出现浏览器原生 `This page couldn't load`；旧页面能恢复到新版本；API 和媒体任务异常有明确提示。

### P2.3 长片、弱网与生命周期稳定性

- [ ] MP4 Range 与 HLS 各连续播放 90 分钟，记录首帧时间、缓冲次数、丢帧和音画漂移。
- [ ] 对同一长片执行前后拖动各 20 次，并覆盖片头、片中、片尾和未生成分片。
- [ ] 覆盖 Wi-Fi 断开 10/30 秒、头显待机唤醒、标签页后台恢复、WebXR 反复进入退出 20 次。
- [ ] 两台头显并发播放时验证任务调度、GPU 饱和保护、缓存租约和磁盘配额。
- [ ] 导出经过脱敏的本地诊断包，包含版本、能力判断、播放路径、网络错误和 FFmpeg 摘要，不包含媒体路径、Cookie 或网盘 Token。

验收标准：失败后能够继续播放或明确回退；不出现画面冻结但字幕继续、无限生成、位置循环跳转或缓存越界。

### P2.4 HDR / 高位深真机验收

- [ ] 为 HDR10、HLG、10-bit SDR 准备带可验证色条、灰阶和高光的精确样片。
- [ ] 在每类头显上验证默认兼容流的亮度、色偏、渐变色带和暗部细节。
- [ ] 完整执行人工显示确认的创建、90 日过期、浏览器升级、来源变化、媒体变化、撤销和存储损坏矩阵。
- [ ] 原片解码失败、停帧或呈现异常时自动回到兼容流，并尽量保持播放位置。
- [ ] 杜比视界和色彩未知素材继续保持未认证兼容路径，不以“能播放”推断色彩正确。

验收标准：页面标签、实际网络路径和诊断内容一致；`guided-user` 只表示人工观感确认，不能显示为端到端 HDR 已验证。

### P2.5 真实网盘账号闭环

- [ ] 使用测试专用百度账号完成设备码登录、应用目录索引、完整缓存、播放、Token 刷新和 dlink 过期恢复。
- [ ] 使用测试专用夸克账号完成官方授权、搜索、完整下载、重启恢复和授权过期处理。
- [ ] 覆盖 429/限速、断网、磁盘不足、取消任务和源移除；完成前的半文件不得进入媒体库。
- [ ] 对自有测试文件验证大小与 ffprobe；上游提供校验和时进行强校验，否则明确记录完整性证据等级。
- [ ] 抓包与诊断不得包含 Token、FID、dlink、密码或第三方上游地址，头显只访问 Localis 同源 URL。

验收标准：百度和夸克各至少一个真实测试账号完成“登录—索引—缓存—播放—重启恢复”，并通过故障与脱敏矩阵；协议模拟不能替代此项。

### P2.6 发布与隐私门槛

- [ ] 在 Windows CI 上执行 Lint、TypeScript、全部测试、生产构建和基础媒体烟雾测试。
- [ ] 使用当前源码重新生成安装版和便携版；现有仍采用旧 AI 行为的 0.3.0 产物不得作为本轮功能发布。
- [ ] 在清洁 Windows 虚拟机完成安装、配对、卸载、升级保留配置和关键播放路径烟雾测试。
- [ ] 生成 SHA-256、SBOM、第三方许可清单和可复现的发布记录。
- [ ] 发布前执行密钥、证书、网盘凭据、本地绝对路径和大文件扫描。
- [ ] 审计生产 CSP 对 `unsafe-eval` 的依赖；能移除时收紧策略，必须保留时记录原因、影响和回归测试。
- [ ] 更新测试报告中的自动化数量、设备证据和明确未通过项。

P2 完成条件：自动化质量门槛通过，三类头显必测项、百度与夸克真实账号闭环完成，至少一次真实可信 HTTPS 部署完成，90 分钟稳定性与构建重启回归通过。

## P3：影像、音频、格式与网盘体验

P3 目标是缩小与原生 XR 播放器在影音体验上的差距，同时保持浏览器零安装和电脑端私有处理。

### P3.1 多音轨、字幕与空间音频

- [ ] 增加多音轨枚举、语言/声道标签和播放中切换。
- [ ] 对 AC-3、E-AC-3、DTS、TrueHD 等浏览器不稳定音轨提供明确的电脑端兼容策略。
- [ ] 验证双声道、5.1 下混、响度和音画同步；空间音频仅在目标浏览器能力明确时开放实验路径。
- [ ] 增加多字幕轨选择、样式、延迟校正和 WebXR 内可读性设置。
- [ ] 评估 PGS/VobSub 的本地 OCR，默认不上传字幕图像，不阻塞普通文本字幕。

验收标准：轨道切换不重置影片位置；连续播放 30 分钟音画偏差在既定阈值内；不支持的音轨不会造成静音播放。

### P3.2 格式与投影覆盖

- [ ] 建立 HEVC、AV1、VP9、H.264 各 profile/level 的真实设备解码矩阵。
- [ ] 在可确定提取兼容基底时研究杜比视界回退；无法证明时继续使用色彩未知兼容标签。
- [ ] 增加投影和立体布局的自动建议，用户确认后才保存，不静默覆盖原文件元数据。
- [ ] 评估 fisheye、cubemap 和常见相机 VR180 元数据；ISO/BDMV/MVC 先完成技术与许可评估再决定范围。

验收标准：每种新增格式都有真实样片、预期路径、错误回退和设备矩阵，不能只依赖 `canPlayType`。

### P3.3 画质与自适应传输

- [ ] 使用标准测试图比较色调映射算子、峰值压缩、色域映射和抖动效果，并固化回归样片。
- [ ] 为不同网络和设备增加可解释的 HLS 自适应码率梯度，防止弱网反复缓冲。
- [ ] 保持“超分绝不偷偷缩小”规则；超过设备或编码上限时显示明确原因。
- [ ] 为传统超分和 AI 清晰增加短预览对比，再决定是否完整处理影片。
- [ ] 记录 VMAF/SSIM 等离线指标，但最终画质结论仍以真机观看和原始参考为准。

验收标准：路径标签包含实际分辨率、码率、位深和色彩转换；弱网降档可恢复；画质模式不会伪装成原生 HDR 或无损增强。

### P3.4 网盘断点续传与长期缓存

- [ ] 增加持久任务与 Range 断点续传、校验失败重试、原子入库和用户可见的缓存清理/固定保留。
- [ ] 使用 remote ID、ETag、修改时间和探测元数据精确失效缓存，不能复用已变化的源文件或显示档案。
- [ ] 为大目录增加增量索引、分页、取消和重启恢复，避免每次启动全量下载元数据。
- [ ] 云盘播放始终经 Localis 同源 URL；头显不得看到第三方下载地址、文件 ID 或凭据。
- [ ] 评估新的网盘连接器时优先官方只读 API，不接入需要把账号凭据交给第三方云服务的捷径。

验收标准：真实账号清单通过；网络中断和配额不足可恢复；源文件哈希一致；移除连接后凭据与媒体索引按设计清理。

### P3.5 AI 与资源调度

- [ ] 增加 AI 预览、取消、暂停、持久检查点恢复和预计磁盘占用。
- [ ] 研究逐眼 VR180、环绕 VR360 的接缝安全 AI 模型或分块策略，未验证前继续禁用不安全组合。
- [ ] 根据 GPU、显存、温度、编码速度和活动播放者动态调度 AI/FFmpeg 任务。
- [ ] 模型版本进入缓存键和诊断；升级模型后不能误用旧缓存。
- [ ] 所有模型与推理继续在电脑本地运行，并在发布包中记录来源、许可和哈希。

P3 完成条件：真实网盘账号闭环通过；多轨/字幕与长时音画同步通过；新增格式和画质模式都有真机证据及安全回退。

## P4：产品化与可维护性

- [ ] 将 HTTPS 配置做成电脑端向导，支持证书申请、续期、DNS 检查和路由器 rebinding 提示。
- [ ] 购买并接入 Windows 代码签名，建立稳定版/测试版发布通道和可回滚更新。
- [ ] 增加本地资源仪表盘：并发任务、GPU、缓存、磁盘、网络和错误历史。
- [ ] 增加脱敏日志轮转、就绪检查和诊断导出，覆盖 FFmpeg、AI 运行时、缓存、磁盘与网盘连接器。
- [ ] 增加配置备份/恢复，但默认排除会话 Cookie、证书私钥和网盘 Token；敏感数据迁移必须显式加密。
- [ ] 建立性能基准机与低端 GPU/纯 CPU 降级矩阵。
- [ ] 研究仪器测量或厂商证明的显示能力证据；在获得强证据前，不把人工确认升级为“已验证 HDR”。

## 暂不承诺的范围

- DRM、商业流媒体解密、加密光盘和绕过平台访问控制。
- 未经许可的杜比视界认证输出、蓝光菜单和专有加密容器。
- 默认把媒体上传到公网云端进行转码、AI 或中继。
- 仅凭浏览器 API、成功解码或主观一次观看就声称全设备 HDR/空间音频兼容。

## 建议的下一批执行顺序

1. 构建产物原子切换与旧页面版本恢复。
2. 真实域名 HTTPS 签发和局域网解析验收。
3. Quest、PICO、Vision Pro 的基础 WebXR 与 30 分钟播放矩阵。
4. 90 分钟长片、弱网、待机和并发 soak test。
5. HDR10/HLG/10-bit SDR 的真机兼容流与人工确认矩阵。
6. 真实百度与夸克账号闭环及故障恢复。
7. Windows CI、当前安装包重建和测试报告更新。
8. 多音轨、字幕与自适应画质。
